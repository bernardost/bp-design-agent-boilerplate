# The work happens in the playground, and every iteration is kept
Date: 2026-10-08 · Status: accepted

## Context

The owner had run a playground app in a design-system repo for a year: one route per
prototype, desktop and mobile frames rendered as CSS containers so one DOM served both,
review controls persisted and shareable by URL, and a graduation command that moved a finished
prototype into the component packages. It worked. Two things did not: the controls were a
header band of segmented controls that took real estate off every screen whether or not anyone
was adjusting them, and iterations overwrote each other, so going back to what the owner had
seen last week meant git archaeology.

The workspace had `/prototype`, which built a first pass with a tuning drawer but said nothing
about where the file lived, how it was versioned, or what happened when the owner said it was
done. `/explore` filed specimens at 4:3 and stopped.

## Decision

- **`brain/playground/<slug>/` holds the work as HTML**: a `piece.md` record and numbered
  version files, `vNN-<what-changed>.html`, that open straight from disk. An existing design
  arrives as an exact as-is `v01`; a new one as a first pass. Pieces are committed; the index
  and each piece's `versions.js` are regenerated by `brain/playground.py` and ignored.
- **A change the owner might want to walk back is a new file, and the previous file is never
  edited again.** The rule is in the charter's always-on list, the agent announces each new
  version in one line, and the version menu in the bar is how the owner goes back.
- **One shared chrome, `_canvas/`.** Artboards are CSS containers named `screen`, so a
  piece's breakpoints are `@container screen` rules and the mobile board is 390px on a 1440px
  display, with no zoom. The controls panel is hidden until `C`, overlays the canvas, and is
  built from a declarative `controls` list; states are presets shown as chips in the bar.
  Copy settings, Reset and Replay are the three actions, as in `/prototype`.
- **`/promote` is how a piece leaves**: the decision naming the version and settings, the
  freeze, implementation notes in the implementer's terms, and — after it ships —
  `shipped.html`, the HTML counterpart of what went live, with its deviations listed.
- `/prototype` now builds into a piece; `/explore` hands a surviving direction to it.
  `doctor.py` reports an unlogged version, a final piece with no decision, and a shipped
  piece with no counterpart.

## Consequences

- Clones made before today take `brain/playground.py`, the canvas, the template and the
  skills through `/update`; the charter and README lines are merge files and get ported by
  hand.
- A design written with `@media` queries does not respond inside an artboard. The translation
  to `@media` happens once, at promotion, and the notes say so.
- The chrome runs on `file://` with no server. Screenshots in a session need one
  (`python3 -m http.server`), because the browser tooling refuses `file:` URLs.
- The template's own example piece lives in `_template/piece.html` and is the only worked
  example; a clone's `/setup` leaves it alone because the folder is template-owned.
