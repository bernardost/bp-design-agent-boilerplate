02
The problemWhy a folder, and not a chat

Every new session starts without knowing what your project is

You re-explain the client, the constraints and last week's decision. Then the window fills up and you do it again.

bp02 / 11
03
The ideaOne repo per project

One repo per project holds everything the agent needs to know

Decisions, open questions, the current state, the research. Plain markdown, in folders, versioned.

bp03 / 11
04
ContextWhere the boundary sits

The boundary is a folder you control, not a retrieval system

Nothing bleeds between clients. That stops being a nicety when two of them have you under NDA.

bp04 / 11
05
OwnershipFixing what it knows

You correct what the agent knows by editing a file

Not by arguing with a memory you cannot see or address. Every change is a commit, so you can read what it learned and when.

bp05 / 11
06
ModelsWhat reads the charter

The charter is plain text, so any model can read it

Switch between sessions, or run two at once in separate tabs. Nothing here expires when a product does.

bp06 / 11
07
The commandsWhat it already knows how to do

The work it already knows how to do is design work

/briefState the project back, and get it agreed
/moodboardResearch becomes ideas, ideas become visions
/exploreSix to eight directions, with real specimens
/critiqueScore a render until it holds up
/deckA deck an agency would hand over
/transcriptAsk what the recording got wrong
/workshopQuestions a stakeholder answers on a phone
/closeWrap the session so the next one knows

PortabilityWhere you can read it
